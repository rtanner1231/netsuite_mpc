# Get Script Logs (`netsuite_get_script_logs`)

[← Back to Tools Overview](../tools-overview.md)

## Description & Usage

`netsuite_get_script_logs` retrieves up to the **last 500 execution logs** (`scriptnote` records) from NetSuite via the MCP Services RESTlet (`rl_mcp_services.js`), sorted most-recent first (`timestamp` descending).

### Three Ways to Query Logs
1. **By Script ID (`scriptId`):** Pass a custom script ID (`'customscript_my_ue'`, `'custevsub_my_sub'`, or unprefixed `'my_ue'`) or a numeric internal script ID (`'1234'`) to fetch logs across all deployments of that script.
2. **By Script File Name (`scriptFileName`):** Pass a script file name or path (`'ue_salesorder.js'` or `'TypeScripts/ue_salesorder.ts'`) to fetch logs for the script record linked to that File Cabinet file.
3. **For `netsuite_run_function` Calls (`runFunctionLogs: true`):** Pass `runFunctionLogs: true` to fetch the last 500 execution logs generated by calls to [`netsuite_run_function`](./netsuite_run_function.md) (which execute under the active environment's configured MCP Services RESTlet `scriptId` and `deploymentId`).

### Input Parameters

| Parameter | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `scriptId` | `string` | No* | Custom script ID (e.g., `'customscript_my_ue'`, `'custevsub_my_sub'`) or numeric internal ID. Mutually exclusive with `scriptFileName` (unless `runFunctionLogs: true`). |
| `scriptFileName` | `string` | No* | Script file name or path (e.g., `'ue_salesorder.js'` or `'src/TypeScripts/ue_salesorder.ts'`). Mutually exclusive with `scriptId` (unless `runFunctionLogs: true`). |
| `runFunctionLogs` | `boolean` | No* | If `true`, retrieves the last 500 execution logs from the MCP Services RESTlet deployment (`config.scriptId` and `config.deploymentId`) generated during `netsuite_run_function` executions. |

*\*Provide either `scriptId`, `scriptFileName`, or `runFunctionLogs: true`.*

## Complementary Tools

- **[Run Function (`netsuite_run_function`)](./netsuite_run_function.md):** Pair `netsuite_run_function` with `netsuite_get_script_logs({ runFunctionLogs: true })` to inspect `N/log` debug/error output emitted during dynamic function testing.
- **[Search Scripts (`netsuite_search_scripts`)](./netsuite_search_scripts.md) & [Get Script (`netsuite_get_script`)](./netsuite_get_script.md):** Find a script's `scriptId`, `fileName`, or current deployment `logLevel` (`DEBUG`, `AUDIT`, `ERROR`, `EMERGENCY`) before fetching its logs.
- **[Deploy Script (`netsuite_deploy_script`)](./netsuite_deploy_script.md):** Update a deployment's `logLevel` to `'DEBUG'` if debug logs are not being captured, or deploy code fixes after diagnosing errors in the logs.

## Inner Workings

1. **Input Validation & Mode Dispatch (`src/tools/getScriptLogs.ts`):**
   - **Mode A (`runFunctionLogs: true`):** Reads the active environment's `config.scriptId` and `config.deploymentId` from `env.json` via `getEnvironmentConfig()` and dispatches `{ action: "SCRIPT_LOGS_BY_ID", scriptId: config.scriptId, deploymentId: config.deploymentId }`.
   - **Mutual Exclusion Validation:** If `runFunctionLogs` is not true, validates that the caller provided either `scriptId` OR `scriptFileName` (returning a validation error if both or neither are provided).
   - **Mode B (`scriptId` provided):** Dispatches `{ action: "SCRIPT_LOGS_BY_ID", scriptId: rawScriptId }`.
   - **Mode C (`scriptFileName` provided):** Extracts the base file name (`rawFileName.split(/[\\/]/).pop()`) and dispatches `{ action: "SCRIPT_LOGS", scriptFileName: normalizedFileName }`.

2. **RESTlet SuiteQL Log Queries (`handleScriptLogs` & `handleScriptLogsById` in `rl_mcp_services.js`):**
   - **By File Name (`handleScriptLogs`):**
     - Converts any `.ts` extension on `scriptFileName` to `.js` (`toJsExtension`) and runs a SuiteQL query joining `script s`, `file f ON f.id = s.scriptfile`, and `LEFT JOIN scriptnote n ON n.scripttype = s.id` where `f.name = '<fileName>'`, ordering by `n.date DESC` (`SELECT top 500 ...`).
   - **By Script ID (`handleScriptLogsById`):**
     - If `scriptId` is numeric (`/^\d+$/`), filters on `s.id = <number>`.
     - If `scriptId` is a string, strips any `.xml` suffix and builds candidate IDs handling standard scripts (`customscript_*`), Event Subscribers (`custevsub_*`), and NetSuite's internal SuiteQL `_script` suffix on Event Subscribers (`custevsub_<id>_script`), matching via `UPPER(s.scriptid) IN (...)`.
     - If `deploymentId` is also present (when `runFunctionLogs: true`), joins `scriptdeployment d ON d.script = s.id` and matches either numeric `(d.version = <num> OR d.primarykey = <num>)` or `UPPER(d.scriptid) = UPPER('<deploymentId>')`.

3. **Formatting & Timestamp Sorting (`queryAndFormatScriptLogs`):**
   - Because the query uses a `LEFT JOIN` onto `scriptnote`, if a script exists in NetSuite but currently has 0 execution logs, the query still returns 1 row with `script_name` and `script_type` and `null` note columns—allowing the tool to return `{ success: true, scriptName, scriptType, logs: [] }` rather than a false "script not found" error.
   - Maps each valid `scriptnote` row to `{ timestamp, title, message, type }` (where `timestamp` is formatted via `TO_CHAR(n.date, 'YYYY-MM-DD HH24:MI:SS')`) and sorts `logs` descending by timestamp.
