# Settings & Configuration Guide

The NetSuite MCP Server (`@rtanner1231/netsuite-dev-mcp`) provides a multi-environment, profile-driven configuration system designed to balance **developer velocity**, **token efficiency**, and **strict security guardrails**.

You can manage every setting visually through the built-in **Graphical Settings Web UI** (`/open-settings` / `netsuite_open_settings`) or by editing JSON configuration files directly on disk.

## 1. Configuration Storage & Live Reloading

All global configuration files and schema databases are stored in your operating system's application data directory (`MCP_DIR`):

- **macOS / Linux:** `~/.config/netsuite_mcp/` *(or `$XDG_CONFIG_HOME/netsuite_mcp/`)*
- **Windows:** `%APPDATA%\netsuite_mcp\` *(typically `C:\Users\<user>\AppData\Roaming\netsuite_mcp\`)*

### Files in the Configuration Directory

| File / Directory | Required? | Purpose |
| :--- | :---: | :--- |
| `env.json` | **Yes** | Stores your NetSuite environments (e.g., `Sandbox`, `Prod`), their OAuth 1.0a / RESTlet / SDF credentials, and each environment's map of tool `profiles`. |
| `state.json` | **Yes** | Tracks the currently active `environment` and `profile` (e.g., `{"environment": "Sandbox", "profile": "developer"}`). |
| `config.json` | Optional | Stores global project build/upload settings (`project`) and default SDF XML attributes (`objectDefaults` for `RECORD`, `FIELD`, and `LIST`). |
| `<Environment>.db` | Recommended | SQLite schema database for `<Environment>` (generated by `MCPSchemaLoad.html`). Powers `netsuite_get_fields`, `netsuite_get_related_tables`, and vector indexing. |
| `<Environment>.lance/` | Recommended | LanceDB vector embeddings directory built from `<Environment>.db`. Powers semantic search in `netsuite_search_tables`. |
| `.settings-session.json` | Auto-managed | Persists the local Settings Web UI port and session security token so an open browser tab reconnects seamlessly across MCP restarts. |

### Zero-Config Startup & Live File Watching

- **Unconfigured Startup:** Before `env.json` and `state.json` exist, the server starts cleanly and exposes only the three always-available bootstrap tools:
  - [`netsuite_open_settings`](./tools/netsuite_open_settings.md) (Prompt: `/open-settings`)
  - [`netsuite_list_environments`](./tools/netsuite_list_environments.md) (Prompt: `/list-environments`)
  - [`netsuite_switch_environment`](./tools/netsuite_switch_environment.md) (Prompt: `/switch-environment`)
- **Real-Time Config Watcher:** The MCP server watches `state.json`, `env.json`, and `config.json` using both `fs.watch` and a 2-second fallback signature poll. Whenever changes are saved (via the Settings UI, `netsuite_switch_environment`, or a text editor):
  1. Ineligible in-memory session overrides are pruned (or cleared if the active environment/profile changed).
  2. The server emits an MCP `notifications/tools/list_changed` event to your AI client so the exposed tool list updates immediately.
  3. Connected Settings UI browser tabs receive a Server-Sent Event (`/api/events`) and refresh automatically.

## 2. Using the Graphical Settings Web UI

To launch the graphical configuration page, invoke the **`/open-settings`** prompt or ask your AI assistant to run [`netsuite_open_settings`](./tools/netsuite_open_settings.md).

The server starts a local-only HTTP server bound to `127.0.0.1` (default port `45821`) protected by a 24-byte cryptographic query token (`http://127.0.0.1:45821/?token=...`) and opens it in your default browser.

### What You Can Do in the Settings UI

1. **Manage Environments:**
   - Add, rename, duplicate, or delete NetSuite environments (e.g., `Sandbox`, `Prod`, `QA`).
   - *(Note: If you rename an environment in the UI and click **Save Changes**, any existing `<OldName>.db` and `<OldName>.lance` databases on disk are automatically renamed to `<NewName>.db` and `<NewName>.lance`.)*
2. **Test NetSuite Connections & Download Companion NetSuite Files:**
   - Switch to the **Resources** tab at the top of the UI to download the exact version-matched NetSuite files (**Download `rl_mcp_services.js`** and **Download `MCPSchemaLoad.html`**) directly from the running MCP package.
   - Click **Test Connection** on any environment tab to immediately test your OAuth 1.0a credentials and MCP RESTlet deployment (`SELECT 1 AS ping` via `RUN_SUITE_QL`) before saving.
3. **Manage Schema (`.db`) & Vector (`.lance`) Databases:**
   - **Load SQLite Database (.db)...**: Pick a `.db` file downloaded from `MCPSchemaLoad.html` (up to 250 MB). The server verifies the SQLite 3 header, checks that the `tables` and `tablefields` tables exist, reports the total table and field counts, and atomically saves it to `<MCP_DIR>/<Environment>.db`.
   - **Download Existing .db**: Download the environment's current `<Environment>.db` file to your machine so you can pass it into `MCPSchemaLoad.html` for incremental custom record or single-table updates.
   - **Build / Rebuild Vector Database (.lance)**: Triggers a background vector embedding build (`Xenova/bge-small-en-v1.5`) from `<Environment>.db` and displays a live progress bar showing the phase, indexed table count, and elapsed time.
4. **Configure Tool Profiles & Guardrails:**
   - Select the active **Environment** and **Profile** at the top of the UI, or create custom profiles per environment using one-click **Profile Presets**, category switches, hard guardrails, guardrail exceptions, and per-tool overrides.
5. **Configure Global Project & SDF Object Defaults:**
   - Switch to the **Global Settings** tab to configure TypeScript/SDF build behavior and default XML attributes for new Custom Record Types, Custom Fields, and Custom Lists.

## 3. Core Concepts

### Environments & Credentials

Each environment in `env.json` represents a specific NetSuite account (e.g., `Prod`, `Sandbox`) and contains the following credential fields:

| Field Key | UI Label | Required? | Description |
| :--- | :--- | :---: | :--- |
| `accountId` | Account ID | **Yes** | Your NetSuite Account ID (e.g., `1234567` or `1234567-sb1`). Used to construct RESTlet/REST API URLs (lowercased with `_` converted to `-`) and the OAuth 1.0a `realm` header (uppercased with `-` converted to `_`). |
| `sdfId` | SDF Auth ID (SuiteCloud CLI) | No | The SuiteCloud CLI authentication ID (`authid` created via `suitecloud account:setup`). **If left blank, all tools with `requiresSdf: true` are automatically disabled for this environment.** |
| `scriptId` | RESTlet Script ID | **Yes** | Numeric internal ID (e.g., `1234`) or custom script ID (e.g., `customscript_rl_mcp_services`) of the deployed `rl_mcp_services.js` RESTlet. |
| `deploymentId` | RESTlet Deployment ID | **Yes** | Numeric deployment ID (e.g., `1`) or custom deployment ID (e.g., `customdeploy_rl_mcp_services`) of the deployed `rl_mcp_services.js` RESTlet. |
| `consumerKey` | OAuth Consumer Key | **Yes** | Consumer Key from your NetSuite Integration Record. |
| `consumerSecret` | OAuth Consumer Secret | **Yes** | Consumer Secret from your NetSuite Integration Record. |
| `token` | OAuth Token ID | **Yes** | Token ID from your NetSuite Access Token. |
| `tokenSecret` | OAuth Token Secret | **Yes** | Token Secret from your NetSuite Access Token. |

### Tool Categories & Lean Startup Footprint

The server organizes its 33 domain tools into **9 functional categories** (plus 4 environment/toolset management tools):

| Category ID | Category Title | Tools in Category | Enabled at Startup by Default? |
| :--- | :--- | :--- | :---: |
| `table_discovery` | **Table & Schema Discovery** | `netsuite_search_tables`, `netsuite_get_fields`, `netsuite_get_related_tables`, `netsuite_rebuild_vector_database`* | **Yes** *(except `netsuite_rebuild_vector_database`, which is in `disabledTools` by default)* |
| `data_operations` | **Data Querying & Record Operations** | `netsuite_run_suite_ql`, `netsuite_load_record_sample`, `netsuite_upsert_record` | **Yes** |
| `report_creation` | **Report Creation (Saved Searches & Datasets)** | `netsuite_view_saved_search`, `netsuite_create_saved_search`, `netsuite_view_dataset`, `netsuite_create_dataset` | No (On-Demand) |
| `script_execution` | **Script Execution & Log Inspection** | `netsuite_run_function`, `netsuite_get_script_logs` | No (On-Demand) |
| `sdf_file_deployment` | **File Cabinet & SDF Files** | `netsuite_view_file`, `netsuite_upload_file`, `netsuite_compare_files` | No (On-Demand) |
| `script_management` | **Script Management** | `netsuite_deploy_script`, `netsuite_get_script`, `netsuite_search_scripts` | No (On-Demand) |
| `custom_objects` | **Custom Objects (Records, Fields & Lists)** | `netsuite_view_custom_object`, `netsuite_upsert_custom_record_type`, `netsuite_upsert_custom_field`, `netsuite_upsert_custom_list` | No (On-Demand) |
| `translations` | **Translation Collections** | `netsuite_list_supported_locales`, `netsuite_list_translation_collections`, `netsuite_view_translation_collection`, `netsuite_create_translation_collection`, `netsuite_update_translation_collection` | No (On-Demand) |
| `templates` | **Templates (Advanced PDF & Email)** | `netsuite_list_templates`, `netsuite_read_advanced_pdf_template`, `netsuite_upsert_advanced_pdf_template`, `netsuite_render_advanced_pdf_template`, `netsuite_read_email_template`, `netsuite_upsert_email_template`, `netsuite_render_email_template` | No (On-Demand) |

#### Why Only Two Categories Are Enabled at Startup by Default
Exposing all 37 detailed tool schemas at once consumes thousands of context tokens on every turn and can reduce tool-selection accuracy on smaller models. By starting with only `table_discovery` and `data_operations` (6 core tools + 4 management tools), daily queries stay fast and lean while specialized categories can be unlocked on-demand in seconds.

### Dynamic On-Demand Toolset Activation

When a profile has **`allowDynamicActivation: true`** (the default):
1. The server exposes the [`netsuite_manage_toolsets`](./tools/netsuite_manage_toolsets.md) tool.
2. The description of `netsuite_manage_toolsets` is **dynamically generated** on every `ListTools` request to show the AI agent every available category and every eligible inactive tool (along with a 1-line summary of each).
3. If you ask the AI to perform a task outside its current startup tools (e.g., *"Render our Sales Order PDF template"* or *"Create a saved search for open invoices"*), the AI calls `netsuite_manage_toolsets` with `action: "activate"` for either the specific tool (`tools: ["netsuite_render_advanced_pdf_template"]`) or the full category (`categories: ["report_creation"]`).
4. The toolset change is stored **in memory only** for the current MCP session (never mutating `env.json`) and triggers `sendToolListChanged()` so the AI can immediately use the unlocked tools.
5. **Automatic Reset:** Any temporary session toolset overrides are automatically cleared whenever you switch environments or profiles (or call `netsuite_manage_toolsets` with `action: "reset"`).

If you set **`allowDynamicActivation: false`** on a profile, `netsuite_manage_toolsets` is completely hidden, locking the session strictly to the profile's startup tools.

### Tool Profiles & Built-In Presets

Every environment in `env.json` has a `profiles` dictionary. All profiles within an environment **share the same NetSuite credentials and SQLite/LanceDB databases**, but define their own tool visibility and security guardrails.

- A permanent **`default`** profile is always present on every environment.
- You can create as many additional profiles as you like (e.g., `readonly`, `developer`, `admin`, `reporting`) and switch between them at any time via the Settings UI or by calling [`netsuite_switch_environment`](./tools/netsuite_switch_environment.md) (or the `/switch-environment` prompt).

#### Built-In Profile Presets in the Settings UI

When creating or editing a profile in the Settings UI, you can quick-apply any of these 6 presets:

| Preset ID | Title | `disableDestructive` | `disableSdf` | `allowDynamicActivation` | `enabledCategories` at Startup | Default `disabledTools` |
| :--- | :--- | :---: | :---: | :---: | :--- | :--- |
| `core` | **Core (Default)** | `false` | `false` | `true` | `table_discovery`, `data_operations` | `netsuite_rebuild_vector_database` |
| `readonly` | **Read-Only Analyst** | `true` | `true` | `true` | `table_discovery`, `data_operations` | `netsuite_rebuild_vector_database` |
| `developer` | **SuiteScript Developer** | `false` | `false` | `true` | `table_discovery`, `data_operations`, `script_execution`, `sdf_file_deployment`, `script_management` | `netsuite_rebuild_vector_database` |
| `admin` | **Admin & Custom Objects** | `false` | `false` | `true` | `table_discovery`, `data_operations`, `custom_objects`, `script_management` | `netsuite_rebuild_vector_database` |

### Security Guardrails & Precedence Order

A profile controls tool availability through two distinct layers:
1. **Hard Security Guardrails** (cannot be bypassed by the AI via `netsuite_manage_toolsets`).
2. **Startup & Session Visibility** (controls which non-blocked tools are active at startup vs. available on-demand).

#### Profile Properties Reference

| Property | Layer | Type | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `description` | Metadata | `string` | `""` | Optional human-readable description shown in `netsuite_list_environments` and the Settings UI. |
| `blockedCategories` | **Hard Guardrail** | `string[]` | `[]` | Category IDs that are completely locked. No tool in a blocked category can be used at startup or activated dynamically. |
| `blockedTools` | **Hard Guardrail** | `string[]` | `[]` | Individual tool IDs that are completely locked. Never overridden by `enabledCategories`, `enabledTools`, `allowedTools`, or dynamic activation. |
| `disableDestructive` | **Hard Guardrail** | `boolean` | `false` | Blocks all tools with `isDestructive: true` (any tool that creates, updates, uploads, deploys, or executes arbitrary functions in NetSuite) unless the tool is listed in `allowedTools`. |
| `disableSdf` | **Hard Guardrail** | `boolean` | `false` | Blocks all tools with `requiresSdf: true` (any tool that invokes the SuiteCloud CLI) unless the tool is listed in `allowedTools`. |
| `allowedTools` | **Guardrail Exception** | `string[]` | `[]` | Whitelists specific tool IDs to **exempt them from `disableDestructive` and `disableSdf`**. For example, on a Production profile with `disableDestructive: true`, adding `["netsuite_create_saved_search"]` to `allowedTools` permits saving Saved Searches while keeping all other destructive tools blocked. *(Note: `allowedTools` cannot bypass `blockedCategories`, `blockedTools`, or a missing `sdfId`.)* |
| `allowDynamicActivation` | Session Control | `boolean` | `true` | When `true`, exposes `netsuite_manage_toolsets` so the AI can activate/deactivate eligible categories and tools in-memory during a chat session. |
| `enabledCategories` | Startup Visibility | `string[]` | `["table_discovery", "data_operations"]` | Categories whose tools are enabled at session startup. |
| `disabledTools` | Startup Visibility | `string[]` | `["netsuite_rebuild_vector_database"]` | Specific tools inside `enabledCategories` to keep **off at startup**. Unlike `blockedTools`, tools in `disabledTools` **can** still be activated on-demand via `netsuite_manage_toolsets` (when `allowDynamicActivation: true`). |
| `enabledTools` | Startup Visibility | `string[]` | `[]` | Specific tools outside `enabledCategories` to turn **on at startup** without enabling their entire parent category. |

#### Exact Tool Evaluation Order (`getToolDisableReason`)

Whenever the MCP server lists tools (`ListTools`) or executes a tool (`CallTool`), each tool is evaluated in this exact precedence order:

1. **Always-Available Bootstrap Tools:**
   - If `tool.meta.alwaysAvailable === true` (`netsuite_open_settings`, `netsuite_list_environments`, `netsuite_switch_environment`), the tool is **ALWAYS ENABLED**.
2. **`netsuite_manage_toolsets` Visibility:**
   - Enabled if and only if an active environment is loaded and `profile.allowDynamicActivation !== false`.
3. **Hard Guardrail 1 — `blockedCategories`:**
   - If the tool's category is in `profile.blockedCategories` -> **BLOCKED**.
4. **Hard Guardrail 2 — `blockedTools`:**
   - If `tool.name` is in `profile.blockedTools` -> **BLOCKED**.
5. **Hard Technical Prerequisite — Missing `sdfId`:**
   - If `tool.meta.requiresSdf === true` and `config.sdfId` is empty or omitted -> **BLOCKED**.
6. **Hard Guardrail 3 — `disableDestructive` (with `allowedTools` exception):**
   - If `tool.meta.isDestructive === true` AND `profile.disableDestructive === true` AND `tool.name` is NOT in `profile.allowedTools` -> **BLOCKED**.
7. **Hard Guardrail 4 — `disableSdf` (with `allowedTools` exception):**
   - If `tool.meta.requiresSdf === true` AND `profile.disableSdf === true` AND `tool.name` is NOT in `profile.allowedTools` -> **BLOCKED**.
8. **In-Memory Session Tool Overrides (when `allowDynamicActivation !== false`):**
   - If `tool.name` was deactivated in the current session -> **DISABLED (On-Demand)**.
   - If `tool.name` was activated in the current session -> **ENABLED**.
9. **In-Memory Session Category Overrides (when `allowDynamicActivation !== false`):**
   - If the tool's category was deactivated in the current session -> **DISABLED (On-Demand)**.
   - If the tool's category was activated in the current session -> **ENABLED** *(unlocks all tools in the category that passed steps 3–7, including tools in `disabledTools`)*.
10. **Baseline Profile Startup Rules:**
    - **If the tool's category is in `profile.enabledCategories`:**
      - If `tool.name` is in `profile.disabledTools` -> **DISABLED AT STARTUP** (can be activated via `netsuite_manage_toolsets`).
      - Otherwise -> **ENABLED**.
    - **If the tool's category is NOT in `profile.enabledCategories`:**
      - If `tool.name` is in `profile.enabledTools` -> **ENABLED**.
      - Otherwise -> **DISABLED AT STARTUP** (can be activated via `netsuite_manage_toolsets`).

## 4. Global Project & Build Configuration

Tools that work with local SuiteScript files and SDF objects (`netsuite_upload_file`, `netsuite_compare_files`, `netsuite_deploy_script`, `netsuite_get_script`, `netsuite_upsert_custom_record_type`, `netsuite_upsert_custom_field`, `netsuite_upsert_custom_list`, `netsuite_create_translation_collection`, `netsuite_update_translation_collection`, `netsuite_upsert_advanced_pdf_template`, and `netsuite_upsert_email_template`) automatically inspect your local workspace project root (via MCP client `roots/list` or the server's working directory).

You can configure global defaults under the `"project"` key in `config.json` (or via the **Global Settings > Project & Build Defaults** section in the Settings UI):

| Setting Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `sdfSourceDir` | `string` | Auto-detected | Folder relative to the project root where `manifest.xml`, `FileCabinet/`, and `Objects/` live (e.g., `"dist"`, `"src"`, `"."`). If left blank, auto-detected in order: `defaultProjectFolder` in `suitecloud.config.js` -> directory containing `manifest.xml` (`dist`, `src`, `.`) -> directory containing `FileCabinet/` (`dist`, `src`, `.`) -> `dist`. |
| `buildBeforeUpload` | `"auto"` \| `boolean` | `"auto"` | Controls whether `buildCommand` runs before uploading/comparing/deploying files:<br>• `"auto"`: Runs the build if a build script (`package.json` `scripts.build`) or explicit `buildCommand` exists AND TypeScript is used (`.ts` input file, `tsconfig.json`, or `tsRootDir`).<br>• `true`: Always runs the build command.<br>• `false`: Never runs the build command. |
| `buildCommand` | `string` | `"npm run build"` | Shell command executed in the project root when building before file upload or comparison. |
| `tsRootDir` | `string` | Auto-detected | Optional explicit TypeScript source folder relative to the project root (e.g., `"TypeScripts"` or `"src"`). Overrides `tsconfig.json` `rootDir` detection. |
| `jsOutDir` | `string` | Auto-detected | Optional explicit compiled JavaScript output folder relative to the project root (e.g., `"dist/FileCabinet/SuiteScripts"`). Overrides `tsconfig.json` `outDir` detection. |
| `tsconfigPath` | `string` | `"tsconfig.json"` | Relative path to `tsconfig.json` from the project root. |
| `saveObjectsToProject` | `"auto"` \| `boolean` | `"auto"` | Controls whether SDF object XML files (and companion template/translation files + `manifest.xml` dependencies) deployed via the isolated temporary SDF project are copied back into your local project:<br>• `"auto"`: Copies to `<sdfSourceDir>/Objects/...` if `manifest.xml` or `Objects/` exists in your local project.<br>• `true`: Always copies deployed XML files into the local project.<br>• `false`: Never copies (deploys to NetSuite in the background only). |
| `objectsFolderStrategy` | `"branch"` \| `"flat"` \| `"type"` | `"branch"` | Determines where **new** SDF object XML files are saved under `<sdfSourceDir>/Objects/` when synced to your local project:<br>• `"branch"`: `Objects/<git_branch>/<scriptId>.xml` (falls back to `Objects/<scriptId>.xml` if not in a git repo).<br>• `"flat"`: `Objects/<scriptId>.xml`<br>• `"type"`: `Objects/<rootXmlElement>/<scriptId>.xml` (e.g., `Objects/customrecordtype/customrecord_foo.xml`). |

### Project & TypeScript Path Resolution

When you pass a `.ts` or `.js` path to `netsuite_upload_file`, `netsuite_compare_files`, `netsuite_deploy_script`, or `netsuite_get_script`, the server resolves both the **local compiled `.js` file on disk** and the **NetSuite File Cabinet destination path** (`/SuiteScripts/...`) using:
1. Explicit `tsRootDir` / `jsOutDir` settings (if configured).
2. `tsconfig.json` compiler options via the TypeScript Compiler API (`ts.getOutputFileNames`, `rootDir`/`outDir` mapping, or in-place compilation when `outDir` is omitted).
3. Extraction of the `/FileCabinet/...` path segment relative to `<sdfSourceDir>/FileCabinet`.
4. Fallback mapping of `/TypeScripts/...` -> `/SuiteScripts/...` with `.ts` converted to `.js`.

### Syncing Deployed SDF Objects to Your Local Project

All SDF object deployment tools run inside an **isolated temporary SDF project** in your OS temp directory so they never fail on unrelated dirty files in your repository or mutate your repository's `project.json` or `deploy.xml`.

When `saveObjectsToProject` resolves to `true` (or when `saveToProject: true` is passed on an individual tool call):
- **Existing local object XMLs are always updated in-place:** The server recursively searches `<sdfSourceDir>/Objects/` for `<scriptId>.xml`. If found anywhere (even in another subfolder), it updates that exact file in-place to prevent duplicate object definitions.
- **New object XMLs follow `objectsFolderStrategy`:** Saved under `Objects/<git_branch>/<scriptId>.xml`, `Objects/<scriptId>.xml`, or `Objects/<rootElement>/<scriptId>.xml`.
- **Companion files are synced too:**
  - Advanced PDF Templates sync `<scriptId>.template.xml` alongside `<scriptId>.xml`.
  - Email Templates sync `<scriptId>.template.html` alongside `<scriptId>.xml`.
  - Translation Collections sync `Translations/<scriptId>.<locale>.xlf` files into `<sdfSourceDir>/Translations/`.
  - Any newly discovered feature, object, or file dependencies are merged into `<sdfSourceDir>/manifest.xml` if `manifest.xml` exists locally.

### Per-Repository Configuration Overrides

You can override any `"project"` setting on a per-repository basis. The server merges project configuration in the following order of precedence (lowest to highest):

1. Built-in defaults (`buildBeforeUpload: "auto"`, `buildCommand: "npm run build"`, `saveObjectsToProject: "auto"`, `objectsFolderStrategy: "branch"`)
2. Global `~/.config/netsuite_mcp/config.json` (`"project"` section)
3. `<projectRoot>/package.json` (`"netsuiteMcp"` field)
4. `<projectRoot>/project.json` (`"netsuiteMcp"` field)
5. `<projectRoot>/.netsuitemcp.json` (highest precedence)

### `.netsuitemcp.json` / `package.json`

To override project settings inside a specific SuiteCloud / TypeScript repository, create `.netsuitemcp.json` in the repository root:

```json
{
  "sdfSourceDir": "src",
  "buildBeforeUpload": true,
  "buildCommand": "npm run compile",
  "tsRootDir": "TypeScripts",
  "jsOutDir": "src/FileCabinet/SuiteScripts",
  "saveObjectsToProject": true,
  "objectsFolderStrategy": "type"
}
```

Or embed it under `"netsuiteMcp"` in your repository's `package.json`:

```json
{
  "name": "my-netsuite-sdf-project",
  "scripts": {
    "build": "tsc"
  },
  "netsuiteMcp": {
    "sdfSourceDir": "dist",
    "saveObjectsToProject": "auto",
    "objectsFolderStrategy": "branch"
  }
}
```
